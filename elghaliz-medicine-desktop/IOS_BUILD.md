# Building Elghaliz Medicine for iOS

The iOS shell is generated by Capacitor from the React web application. The generated Xcode project is included under `ios/`. It is not a native Swift rewrite and does not by itself add feature parity with the Android project.

## GitHub Actions IPA build

1. Push this folder's contents to your GitHub repository (the workflow is at `.github/workflows/build-ios.yml`).
2. In GitHub, open **Actions → Build iOS IPA → Run workflow** (or push a change to one of the watched paths on `main`/`master`).
3. Download the `Elghaliz-Medicine-unsigned-IPA` artifact from the completed run.

The workflow uses a GitHub-hosted macOS runner and Xcode to compile an iOS `.app`, then packages it in `Payload/App.app` as `Elghaliz-Medicine-unsigned.ipa`. This Windows computer cannot compile the iOS binary locally. The web production build, DRM tests, Capacitor `add ios`, and `cap sync ios` were verified on Windows. The Xcode/CocoaPods build and GitHub workflow have not been run or validated on macOS from this checkout. The generated project in `ios/` is checked in; on macOS, the workflow syncs web assets, installs CocoaPods dependencies (creating/updating the Xcode workspace), then builds that workspace.

## Signing / installing

The artifact is **unsigned**, so it is not ready to install by tapping it or through TestFlight/App Store. Install by re-signing with an appropriate Apple development/distribution certificate and provisioning profile using a supported sideloading tool, or add signing secrets and a separate signing/export step to the workflow. App Store and TestFlight distribution require valid Apple signing and provisioning. Do not upload signing certificates or passwords to source control.

## Current app limitations to verify before release

- `src/config.ts` currently uses an Android Firebase `appId` as a non-empty value, which turns off demo mode; this is not a valid Firebase Web app configuration. Add/register a Firebase Web app, use its web `appId`, and authorize the callback domain/origin before expecting live auth/data.
- Live login currently calls Firebase `signInWithPopup`, then redirects on some errors. Google OAuth and Drive consent need explicit testing in Capacitor/WKWebView; if blocked, integrate a native Google auth flow and configure Firebase credential exchange. Drive upload/download and private content access are not guaranteed to work as-is.
- The desktop/web port is documented as Demo-first and incomplete in backend functionality. Test the required screens and permissions against the Android app before treating this as a production replacement.
- Web overlays and watermark text are not DRM or screenshot prevention. iOS screen capture protections require native implementation and cannot be promised by this wrapper.
